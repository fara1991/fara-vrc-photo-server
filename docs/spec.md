# 仕様（第 1 版・案）

VRChat で写真を撮ったとき、**そのときに操作していたアバターの情報**を、写真ファイルに追記するための、Windows 用の常駐ソフトの仕様です。
追記した情報は、写真ブログ用のデスクトップアプリ（[fara-vrc-photo-album](https://github.com/fara1991/fara-vrc-photo-album)）が、写真の取り込み時に読みます。

この文書は、**2 つのリポジトリで合わせるための取り決め**（第 5・6 節）を含みます。変えるときは、両方を直します。

## 1. 目的と、やらないこと

**目的**
- 写真を撮ったときのアバターの名前（と ID）を、写真ごとに自動で記録する。
- VRChat のログは約 1 日で消えるので、消える前に履歴として手元に残す。

**やらないこと**
- VRChat 本体への改造・DLL の注入・メモリの読み取りなど、VRChat の規約や不正対策（EAC）に触れること。**ログファイルの読み取り**、**OSC の受信**、**写真フォルダの見張り**、**写真ファイルへの追記**だけを行う。
- VRChat のアカウント情報・ログインを扱わない（VRChat の API を呼ばない）。
- 他のプレイヤーの情報を記録しない。**自分のアバターの切り替えだけ**を記録する。
- 自分の表示名を、写真・履歴のどちらにも書かない（ログから「自分の行」を選ぶためにだけ、設定で持つ）。

## 2. 全体の構成

.NET 10 の、タスクトレイに常駐する Windows アプリ。

| 部品 | 役割 |
| --- | --- |
| LogWatcher | VRChat のログ（`output_log_*.txt`）の追記を読み、イベントを取り出す |
| HistoryStore | イベントを、履歴ファイル（`history.jsonl`）に追記する |
| PhotoWatcher | 写真フォルダの新しい PNG を見つける |
| XmpWriter | 写真の XMP に、アバターの情報を追記する |
| （任意・後で）OscListener | OSC で来る `/avatar/change` や、アバターのパラメーター（服の番号など）を履歴に追記する |

流れ: VRChat がログに書く → LogWatcher が読んで履歴に追記 → 写真ができる → PhotoWatcher が見つける → 撮影日時の直前のアバターを履歴から探す → XmpWriter が追記。

## 3. VRChat のログの読み取り

- 場所: `%USERPROFILE%\AppData\LocalLow\VRChat\VRChat\output_log_*.txt`（VRChat が起動中も書き込んでいるので、**読み取り専用・他の書き込みを許す共有**で開く）。ログは約 1 日で消える（確認済みの動作。設定では変えられない）。
- 時刻: 行頭の `yyyy.MM.dd HH:mm:ss`（PC のローカル時刻。写真のファイル名と同じ基準）。
- 取り出す行（この PC の実ログで確認した形。VRChat の更新で変わり得るので、**見つからなければ何も記録しない**）:

| イベント | 行の形 |
| --- | --- |
| ワールドに入った | `[Behaviour] Entering Room: <ワールド名>` と、続く `[Behaviour] Joining wrld_<uuid>:<インスタンス>` |
| アバターの切り替え | `[Behaviour] Switching <表示名> to avatar <アバター名>`（**表示名が、設定の自分の表示名と一致する行だけ**） |
| アバターの ID | `Loading Avatar Data:avtr_<uuid>`（直前の切り替えの行に続けて出る。切り替えの行の後、同じ読み込みの範囲（30 秒以内）の最初のものを、その切り替えの ID とする。見つからなければ ID なし） |

- **実ログでの確認（E1）**: この PC の 4 ファイルで、切り替え 88 件のうち ID が取れたのは 58 件。ID が取れないのは、**キャッシュ済みのアバターのとき**（`Loading Avatar Data` の行が出ない）。名前は、すべて取れる。同じアバター名は、ほぼ同じ ID に対応する（例外が 1 つ。同名の別バージョンの可能性）。そのため、**アバターの特定は、名前を主にして、ID は、取れたときだけ付ける**。
- **`Saving Avatar Data:avtr_…` の行は使わない**。切り替えの直後に出るが、**直前のアバター**の ID で、新しいアバターのものではない（実ログで確認）。
- ワールドの行は、インスタンスの部分（`:49024~private(usr_…)~region(jp)` など。ユーザー ID を含む）を**記録しない**。ワールド名と `wrld_` の ID だけを持つ。
- 読み始めの位置は、起動時に、既存のログすべてを先頭から読み、履歴にまだ無いイベントだけを追記する（イベントは、時刻と種類・内容で重複を判定する）。

## 4. 履歴ファイル

- 場所: `%LOCALAPPDATA%\FaraVrcPhotoServer\history.jsonl`（1 行 1 イベントの JSON。追記のみ。壊れた行は読み飛ばす）。
- 時刻は、ISO 8601 のオフセットつき（例: `2026-10-28T01:49:51+09:00`）。

```json
{"t":"2026-10-28T01:49:39+09:00","type":"world","worldId":"wrld_528e5412-7bb4-42c1-aab2-2b38a629f5de","worldName":"Crystal Garden"}
{"t":"2026-10-28T01:49:51+09:00","type":"avatar","avatarName":"FaraFrillBlood","avatarId":"avtr_71bd1202-157a-4264-b888-a133209de9ca"}
```

- `avatarId` は、見つからなければ省く。
- 表示名・インスタンス・ユーザー ID・位置は、**履歴にも書かない**。
- OSC を足したとき（任意・後で）: `{"type":"param","name":"OutfitId","value":3}` のような行を、同じファイルに追記する。

## 5. 写真への追記（XMP）

- 見張る場所: 写真フォルダ（設定。既定は、そのユーザーの「ピクチャ」の下の `VRChat`（`C:\Users\{ユーザー}\Pictures\VRChat` の形。環境のフォルダの設定に従うので、どのユーザーでも同じ形。写真ブログのアプリも、同じ場所を読む）。サブフォルダ `yyyy-MM` を含めて見る）。
- 対象: `VRChat_yyyy-MM-dd_HH-mm-ss.fff_WxH.png`（古い形の `VRChat_WxH_yyyy-MM-dd_HH-mm-ss.fff.png` も読む。ファイル名の日時が**撮影日時**。ローカル時刻）。
- 作成された直後は、VRChat が書き込み中のことがある。**ファイルの大きさが 1 秒間変わらなくなってから**処理する。
- 撮影日時の直前の `avatar` イベント（最大 24 時間前まで。ワールドに入った後の `avatar` を優先）を、写真のアバターとする。見つからなければ何も書かない。
- 書き込み先: PNG の `iTXt` チャンク（キーワード `XML:com.adobe.xmp`）の、XMP の `rdf:Description` に、**独自の名前空間**の項目を足す。VRChat が書いた既存の項目（`vrc:` と `xmp:`）は、変えない。

```xml
xmlns:faraxml="http://fara-labs.com/ns/faraxml/1.0/"
faraxml:Version="1"
faraxml:AvatarName="FaraFrillBlood"
faraxml:AvatarId="avtr_71bd1202-157a-4264-b888-a133209de9ca"
faraxml:Source="log"
```

- `AvatarId` は、分かったときだけ。`Source` は、取り出した方法（`log` または、後で足す `osc`）。
- **すでに `faraxml:` の項目がある写真は、書き換えない**（二重に書かない）。
- 書き込みの手順: 1) 元のファイルを読んで検査する（PNG として読めること）→ 2) 新しい内容をメモリに作って検査する（PNG として読めること・画像のデータが元と同じこと・追記した内容が読めること）→ 3) 書く。
  - **控えを残さないとき（既定）は、写真のファイルに直接書く**: 書く前に、元の内容と記録（どの写真か・元の更新日時）を退避フォルダ（`%LOCALAPPDATA%\FaraVrcPhotoServer\pending`）に書く。写真は、書いている間ほかから開けない（FileShare.None）。先頭から書いて長さを合わせ、更新日時・作成日時は元のままにし、書いたあとに読み直して新しい内容と同じか確かめる。合わなければ、退避から元の内容に戻す。確かめ終えたら退避を消す。退避は、写真のフォルダにも backup にも残さない。直接開けないとき（ほかのプログラムが開いている・読み取り専用）は、次の方法でやり直し、それでもだめなら何も変えない。
    - **電源断・強制終了で、書き込みの途中で止まったとき**: 退避が残る。次回の起動で、写真を検査し、壊れていれば退避から元の内容に戻し、壊れていなければ退避を消す（写真は変えない）。戻せなかったときは、退避を残して、次の起動でまた試す。
  - **控えを残すとき**（設定のチェックボックス）: 元のファイルを backup フォルダにコピーしてから、一時ファイルを書いて入れ替える（入れ替えの前に失敗すれば、元のファイルは変えていない）。
  - **失敗したときは、写真が今どうなっているかを、結果の文に書く**（変えていない・元に戻した・戻せなかった（次の起動で戻す））。入れ替えのあとに更新日時だけ戻せなかったときは、タグは付いたものとして扱い、警告として出す。
- 設定で、写真には書かず、履歴だけにする（`writeXmp: false`）こともできる。

## 6. 写真ブログのアプリ側の読み取り（fara-vrc-photo-album）

取り込み時に、写真のアバターを、次の順で決める。**すでに手で選んだアバターは上書きしない**（空の写真にだけ入れる）。

1. 写真の XMP の `faraxml:AvatarName`（と `AvatarId`）。
2. 無ければ、`history.jsonl`（設定で場所を指定。既定は上の場所）から、撮影日時の直前の `avatar` イベント。

アバターの名前を、アバターのマスタ（`content/avatars.json`）の名前・別名と比べる（**空白を取り、大文字小文字を区別しない**。VRChat の `Fara AlmarianDress` と、prefab の `FaraAlmarianDress` が合う）。合うものが無ければ入れない。
`AvatarId` が `avtr_…` のときは、マスタに `blueprintId` があれば、それも使って合わせる（任意の項目。Unity の prefab の PipelineManager から読む案）。

## 7. 設定（このソフト）

`%LOCALAPPDATA%\FaraVrcPhotoServer\settings.json`。

| 項目 | 既定 | 内容 |
| --- | --- | --- |
| `displayName` | 空 | 自分の VRChat の表示名。空のあいだは何も記録しない |
| `photoFolder` | ユーザーの「ピクチャ」の下の `VRChat` | 写真を見張るフォルダ（**画面には出さない**。ほとんどの人が同じ場所で、入力が要らないため。テスト・特別な環境のための項目） |
| `logFolder` | `%USERPROFILE%\AppData\LocalLow\VRChat\VRChat` | VRChat のログのフォルダ（**画面には出さない**。VRChat が決めた場所で、みんな同じ） |
| `historyPath` | `%LOCALAPPDATA%\FaraVrcPhotoServer\history.jsonl` | 履歴ファイル |
| `writeXmp` | `true` | 写真に追記するか |
| `backupFolder` | 空 | 書く前の元のファイルのコピー先（空ならコピーしない。**画面には出さない**。書き込みは検査つき・失敗しても元は変わらないため。CLI の `--backup` は使える） |
| `backupOriginals` | `false` | **書く前の元の写真を、写真と同じ場所の `backup` フォルダに残す**（例: `…\VRChat\2026-10\backup\VRChat_….png`）。タグを埋め込んだ写真は元の場所にそのまま置く。設定の画面のチェックボックス。見張りは `backup` という名前のフォルダの中を見ない（控えにまた追記しないため。写真ブログのアプリの取り込みも、月のフォルダの直下だけを読むので、控えは出ない） |
| `autoStart` | `false` | Windows の起動時に自動で起動するか（設定ファイルの既定は `false`。インストーラーでは、「Windows の起動時に自動で起動する」が**既定でオン**（チェックが入った状態。外せる）。アンインストールでは、Run の値を消す） |

## 8. プライバシー・安全

- 履歴・設定は、この PC の中だけ。ネットワークには何も送らない。
- 写真に書くのは、アバターの名前と ID だけ。表示名・ユーザー ID・インスタンスは書かない。
- **写真を SNS などに公開するときは、追記したアバターの情報も、ファイルに含まれる**（VRChat 自身が、ワールドの情報を書いているのと同じ）。公開したくないときは、`writeXmp` をオフにする。
- 書き込みは、元のファイルを壊さない手順（第 5 節）に従う。

## 10. 確認結果と未確定

**E2 で確認したこと**: 実際の VRChat の写真（1920x1080・3 MB）のコピーに追記して、(1) 画像として開けて、画素が元と同じ、(2) 元の XMP は 1 文字も変わらず、XML として正しい、(3) 控えのフォルダに元と同じファイルが残る、(4) 2 回目は何もしない、ことを確かめた。実際の写真には書いていない。

- 切り替えの行と `Loading Avatar Data` の対応: 30 秒で足りていた（実ログの 58 件）。ほかのプレイヤーの読み込みの行は、混ざらなかった。ID が無い切り替えが 3 分の 1 ある（第 3 節）。
- ワールドに入った直後のアバターの切り替えが、すべてログに出るか（出ない場合は、直前のワールドの行の後の最初の `avatar` を使う）。
- 写真のファイル名の日時と、ログの時刻のずれ（同じ PC のローカル時刻のはずだが、秒の丸めで 1 秒ほどずれるか）。
- XMP の書き込みで、VRChat 以外のビューア（Windows の「写真」・Twitter など）が問題なく開けるか。

## 11. 常駐ソフト（E3）

- **リンク（ジャンクション）の写真のフォルダ**: Windows は、管理者でない人が作ったジャンクションを「信頼されていないマウントポイント」として、アプリによってはたどれない（「パスをスキャンできません」）。たどれないときは、リンクをたどらずにリンク先のパスを読んで（`ReparseTarget`）、先のフォルダを直接見張る。

- **構成**: `FaraVrcPhotoServer.App`（WinForms のタスクトレイ。画面だけ）と、処理の本体 `PhotoServerService`（Core。画面なしでテストできる）。
- **起動**: 同じ PC で 2 つ動かさない（2 つ目は何もしない）。設定の表示名が空（初回）のときは、設定の画面を開く。設定に問題（表示名が空・フォルダが無い）があるときは、動かさず、トレイの状態に理由を出す。
- **ログの読み続け**（`LogTailer`）: 2 秒ごとに、追記された分だけを読む（ファイルごとに読んだ位置を持つ。行の途中までなら、次の回に続きを読む。ログが短くなったら先頭から）。写真を処理する直前にも読む。
- **ID を待っている切り替えは、ID なしで先に履歴に書く**（写真が、切り替えの直後に撮られても、アバターが分かるように）。ID が分かったら、ID つきを追記する。同じ時刻なら、**ID つきを使う**（`AvatarAt`）。
- **トレイのメニュー**: 状態（見張り中・足りない設定）／設定／最近の処理（新しいものが上。最大 50 件）／写真のフォルダを開く／履歴のフォルダを開く／終了。アイコンの文字（ツールチップ）は、最後の処理。表示名は、どの画面にも出さない。
- **設定の画面**: 表示名・履歴ファイル（初期値は既定の場所。既定のままなら、設定ファイルには空で保存して、既定に従う）・「写真に追記する」・「元の写真を、写真と同じ場所の backup フォルダに残す」・「Windows の起動時に自動で起動する」の 5 つだけ。写真のフォルダ・ログのフォルダ・元の写真の控えのフォルダは、場所が決まっている（または要らない）ので、画面に出さない。保存したら、常駐の本体を作り直す。「閉じる」で、設定のウィンドウだけを閉じる（アプリは、トレイに残る）。
- **自動起動**: 現在のユーザーの `Run` キー（`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`）に、実行ファイルを登録する。管理者の権限は要らない。オフにすると、登録を消す。
- **名前**: 画面に出すアプリ名は `AppInfo.Name`（Core）の 1 か所。名前を変えるときは、ここと、実行ファイル名・README だけ。
